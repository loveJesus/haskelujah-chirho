# Rung 0 inputs: what loading ghc-internal and base needs

2026-11-25, HASKELUJAH/claude_chirho. Design input for steps 4 to 8 of `spec-chirho/tasklists-chirho/26-11-25_14-03-tasklist-next_library_ladder-chirho.md`. It proposes R7 in `26-11-25-plan-revision-chirho.md`.

Measured on the GHC 9.14.1 source tree (`references-chirho/ghc-9.14.1-chirho/ghc-9.14.1` in the union worktree) and on the GHC 9.14.1 installed at `/opt/homebrew/Cellar/ghc/9.14.1`. Closures come from `tools-chirho/import_closure_chirho.py`. That script follows module imports, `SOURCE` imports included, under a small preprocessor model: 64-bit, POSIX, `BIGNUM_NATIVE`, `__GLASGOW_HASKELL__` 914, and both branches kept when a condition cannot be evaluated. The scoreboard replaces it.

## 1. The two packages

- **ghc-internal** (`ghc-internal.cabal.in`, build type `Configure`): Haskell2010 with `NoImplicitPrelude` by default. The module list is 228 exposed and 24 other modules on every target, plus lists that depend on the target and the bignum flag. We choose `bignum-native`, which gives `-DBIGNUM_NATIVE`. The options are `-this-unit-id ghc-internal -Wcompat -Wnoncanonical-monad-instances`. `@ProjectVersionForLib@` is `9.1401`, as in the installed `ghc-internal-9.1401.0`.
- **base** (`base.cabal.in`, build type `Simple`): `NoImplicitPrelude`, 200 exposed modules, one more on POSIX. Almost all of it re-exports ghc-internal.
- **Files** in both `src` trees: 527 `.hs`, 32 `.hsc`, 24 `.hs-boot`. ghc-internal alone has 295 modules and 101,244 lines.
- **Generated modules**: `GHC.Internal.Prim` and `GHC.Internal.PrimopWrappers` (`autogen-modules`). GHC writes both from `compiler/GHC/Builtin/primops.txt.pp`, which itself goes through the preprocessor first. We generate both from the same file.
- **C and Cmm**: on POSIX, 13 C files and 3 Cmm files in `cbits/`. They are not compiled here (decision A6). Each function they provide becomes a Rust runtime entry under its C name.

Proposal:
- **A target profile in Rust.** One table per target. The first target is `aarch64-apple-darwin`, the platform of the installed GHC we compare against. It holds every macro the library tests or expands from the four generated configure headers and `MachDeps.h`: C type sizes and alignments, `HTYPE_*` type mappings, errno and signal values, `HAVE_*` features, platform names.
- **Checked against the real headers.** A test compares each macro the library uses with its value in the installed headers above. The source of the values is GHC's own configure output, so no C compiler runs.
- **Runtime layout is ours.** `DerivedConstants.h`, `Rts.h` and `rts/*.h` describe GHC's C runtime. Their values come from our runtime's own layout table. The modules that use them are runtime-boundary modules.

## 3. `.hsc` modules

There are 32 in all and 11 in the rung 2 closure: `Clock`, `ExecutionStack.Internal`, `Heap.Constants`, `Heap.InfoTable`, `Heap.InfoTable.Types`, `Heap.InfoTableProf`, `InfoProv.Types`, `RTS.Flags.Test`, `Stack.CCS`, `Stack.Constants`, `Stack.ConstantsProf`. All except `Clock` look into the runtime. GHC's `hsc2hs` gets its values by compiling C, which A6 rules out.

Proposal: a small `hsc2hs` in Rust with two modes.
- **Typing mode:** `#type` comes from the target profile. `#const`, `#size`, `#alignment`, `#peek`, `#poke` and `#ptr` become placeholders of the right form. This is enough for `parsed`, `renamed` and `typed`. A declaration from a module read this way stops at `typed`.
- **Full mode:** values come from the target profile for C and OS facts, and from our runtime's layout table for runtime structures. Only this mode can reach `coded`.

Until typing mode exists, these modules sit below `parsed` with the blocker "hsc".

## 4. The size of gate G1

Rung 1 (`Types`, `Classes`, `CString`, `Magic`, `Tuple`) closes over itself: 5 modules and 6,368 lines. It needs only the generated `GHC.Internal.Prim`.

Rung 2's fourteen root modules import 205 of ghc-internal's 295 modules, 83,481 of its 101,244 lines. That includes 26 `SOURCE` edges, all 24 `hs-boot` modules and 11 `.hsc` modules. Module by module, rung 2 is most of the library. The cause is exceptions:
- `error` calls `errorCallWithCallStackException`, and that calls `toExceptionWithBacktrace` and `collectExceptionAnnotation`. `throwIO` does the same.
- `GHC.Internal.Exception.Backtrace` imports the execution-stack backtrace (libdw), the cost-centre stack, and the info-table stack decoder. By default only the `HasCallStack` mechanism is on (`defaultEnabledBacktraceMechanisms`); the other three are off.
- `class (Typeable e, Show e) => Exception e`, so every exception needs `Typeable` evidence. The next checker has no `Typeable` support today: no mention in `tc`, `hir` or the next crate at 3028d1b3.
- In the rung 2 closure there are 155 `ccall`, 36 `capi` and 21 `prim` foreign imports, counted without the preprocessor, so these are upper bounds.

## 5. R7, proposed

1. **Closures by declaration.** The scoreboard follows declaration dependencies, not module imports. A rung gate is stated over the closure of named roots: the rung's exports and each run program's `main`.
2. **Rule 4 checks at run time.** A program runs. Entering a declaration that is neither `coded` nor on the interim list stops the run with "not supported yet: <name>" and its blocker. The stop is a runtime abort that Haskell code cannot catch, with its own exit code. Output already written stays. A run counts as passing only when it completes and equals GHC, so no wrong result is possible. Checked in advance, every program that can call `error` would wait for three backtrace mechanisms that are off by default.
3. **Rung 2 also needs:**
   - built-in `Typeable` evidence, with the type-constructor and module bindings GHC writes for each data type and its fingerprints computed as GHC computes them;
   - `SomeException` with `ExceptionContext`, and the `HasCallStack` backtrace path;
   - top-level `IORef` constants (`unsafePerformIO` with `NOINLINE`);
   - the primops `raise#`, `raiseIO#`, `catch#` and masking;
   - `hsc2hs` typing mode;
   - GHC's top-level handler `runMainIO`, where a run program's uncaught exception text is compared with GHC.
4. **Rule 1 is unchanged.** Rules 1 to 3 still decide every check verdict. Only running moves to run time.
