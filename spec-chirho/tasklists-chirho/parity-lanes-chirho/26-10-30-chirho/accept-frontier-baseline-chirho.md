# The 54-file acceptance frontier: causal audit

Read-only audit on main `75b4e3a9`, 2026-10-30. No compiler, Cargo, GHC, CLI, broker or DB execution by this audit. The committed candidate source and current main have no crate diff. Evidence: each of the 54 source files, its frozen `candidate1-chirho/should_compile-raw-chirho/<file>.stderr`, upstream `all.T`, and the current source paths below. The root's `upstream-cases-chirho.json` retains exact upstream line/options/arguments and source hashes. Root separately reports a fresh GHC 9.14.1 oracle: 46 plain-file accepts and eight rejects; four of those eight accept with their literal upstream defer options. Those oracle executions are parent-reported, not this audit's executions.

The 54 are accounted once in the membership table. A source-supported **first blocker** is not proof that fixing it closes the complete test. `D` means a direct representational/dispatch cause was found in source. `S` means the semantic operation is missing and the source supports that boundary, but the full repair has dependencies. `L` means the diagnostic and relevant code isolate a useful reduction, but a live AST/environment trace is still required before calling the precise root established. The two `L` cases must not be presented as solved root causes.

## First implementation choices

1. **Type equality fixity, two files (D04): measured shared repair.** The shared type-operator lowering consults `operator_fixity_chirho`; `~` is absent and therefore binds at default precedence nine, above `+`. T18252's two explicitly equivalent sides then group differently, and T24845a's addition givens never reach the existing cancellation rule in their intended shape. Root's fresh GHC `:info (~)` confirms **non-associative precedence four**. Root reports the equality-only `0c2b` candidate's complete paired run gains exactly T18252 and T24845a, loses no accepted file, and leaves the rejection axis unchanged. Retain the independent arithmetic negatives before landing; T18252 is unlisted in all.T.
2. **Provider-aware imported schemes (B02/B03):** Parsec's `try` and Set's `insert` currently inherit unrelated globally seeded IO/List schemes. Fix provider identity and the actual schemes, not the final IO/Int error. These are two distinct APIs sharing one import-typing architecture defect.
3. **Strict GADT signatures, two files (D02):** promising shared parser root, but **not** safe as merely consuming `!`. AST Type has no strict field wrapper; GadtCon stores only its type, and Core `collect_constructor_metadata_chirho` explicitly ignores Gadt constructors. A full repair needs a strictness carrier, preserved constructor type/refinement, Core strictness inventory, and bottom/forcing runtime proof. The current zero-field recovery must disappear, while strict fields must not become lazy.
4. **Deriving strategy, three first blockers (D01): HELD, not a one-token landing.** The keyword mismatch is real, but root's prototype newly accepts a valid program and then executes the wrong stock Show implementation. The AST's `Vec<Name>` deriving inventory discards the strategy, and typing selects stock Show before the GND branch. D01 therefore requires a strategy carrier, validation of data/newtype and extension boundaries, and the real newtype runtime route. The measured refinement below supersedes the initial one-token recommendation.
