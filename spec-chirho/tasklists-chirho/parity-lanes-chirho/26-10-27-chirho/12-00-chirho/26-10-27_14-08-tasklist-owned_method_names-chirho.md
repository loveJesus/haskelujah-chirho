## The bug

The dictionary pass's shadow seeding (`transform_module_chirho` in `dict_chirho/rewrite_chirho.rs`) left a top-level binding named like a class method unshadowed whenever its scheme held any predicate of the method's class.
- **The checker keeps an unsigned binding's entailed ground predicate in its inferred scheme.** An unsigned `a + b = 42 :: Int` is `forall t1 t2. (Num Int) => t1 -> t2 -> Int`.
- **So the binding was taken for Num's `+`,** and the pass rewrote each use to `$fNumInt`'s method. That was silent, on every engine.
- **Eq, Ord and Show redefinitions failed the same way.**

## The change (`crates/haskelujah-core-chirho/src/dict_chirho/rewrite_chirho.rs`)

- **Ownership, not inferred type.** Every input binding whose bare name collides with a class method seeds its binder into `local_shadow_ids_chirho`, whatever its scheme. `constrains_quantified_variable_chirho` and its unit test are gone.
- **The producers were traced.** No compiler-generated bare selector reaches the input bindings, so no exception is kept.
  - The pass's input module is the desugarer's output alone (driver `lib.rs`).
  - The desugarer names every compiler-made top-level binding apart: `$prim_<Class>_<method>_<key>` for instance methods and defaults, and `$setField_<field>` for setters.
  - Function bindings, pattern-binding variables and record fields carry the program's own names.
  - The pass generates the class selectors itself, and it already tells compiler-internal names from source binders (`module_source_binder_ids_chirho`).
