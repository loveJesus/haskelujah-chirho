Current State

Full pipeline, green driver suite, GHC drop-in burn-down.

Focus

GHC Drop-in Compatibility

The pipeline is end-to-end and the current push is closing the gap to being a drop-in GHC replacement. Being a drop-in means two things, so we measure both: 850 / 938 (90.6%) of GHC's should_compile corpus type-checks today, and 141 / 767 (18.4%) of GHC's should_fail corpus is correctly rejected. Every fix is gated so it never regresses working programs.

Verified

Driver Suite Green

The driver integration + eval-correctness suite runs at 1734 / 1735 with zero failures. Published compatibility numbers come from timed, generated artifacts — not wishful claims.

What Already Works

Typeclasses Dispatch At Runtime

An evidence-threading pass carries the type checker's resolved instances into the dictionary pass, so class methods dispatch correctly in local, recursive, and binder contexts. Real Hackage packages — constraints, transformers, mtl, deepseq — compile end-to-end.

Honest Edges

Where It Is Still Growing

The biggest gap is soundness, not features: we accept 626 programs GHC correctly rejects. Ordinary errors are caught, but many validity and constraint checks are simply not written yet — so build code you believe is correct, and do not yet rely on us to tell you your code is wrong. Backends are beta and native class-method dispatch is catching up to the STG interpreter. Kept explicit, testable, and documented.

Pipeline

One compiler story, phase by phase.

  1. 01

    Lex + Layout

    Lossless tokens, trivia, and virtual layout tokens for Haskell-style indentation.

  2. 02

    CST Parse + AST Lower

    Recursive-descent parsing into a green tree, then lowering into compiler-friendly AST structures.

  3. 03

    Naming + Module Interfaces

    Resolution across modules, imports, exports, qualified names, and interface-aware downstream compilation.

  4. 04

    Kind + Type Inference

    HM-style type inference with class machinery, deriving support, and exhaustiveness diagnostics layered into the pipeline.

  5. 05

    Core + Runtime Paths

    Core lowering, dictionary passing, simplification, STG-style runtime evaluation, and backend lowering into LLVM IR and Wasm.

Why It Matters

Not a toy parser. A compiler architecture with room to grow.

The project is already past the stage where success means proving the idea. Success now means making the existing architecture harder to break, easier to evolve, and honest about what is stable versus experimental.

What Is Strong

Phase boundaries are clearer, the driver has a shared frontend, the runtime is real, and the workspace has a large passing test corpus.

What Still Bites

Rejection is far behind acceptance — only 18.4% of GHC's should_fail corpus is caught, so unsound programs can slip through. Native (Cranelift/LLVM) class-method dispatch is still catching up to the STG interpreter, some higher-kinded and contextual instances use simplified representations, and monad-transformer runtime shims are simplified beneath GHC-shaped surface types.

Where It Can Go

More real-world package coverage, stronger runtime contracts, faster incremental builds, and clearer backend maturity tiers.

Roadmap

Ship the hardening work without losing the architecture.

Now

Close The GHC Gap

Burn down the remaining GHC compatibility tests, complete the evidence-threading table for higher-kinded instances, and bring native backend dispatch to parity with the interpreter.

Next

Broaden Hackage

Compile more real-world packages end-to-end, finish the Template Haskell / STG bridge, and keep pushing runtime semantics toward full GHC laziness and GC parity.

Later

Grow Targets Without Lying

Keep LLVM, Wasm, Cranelift, JVM, and BEAM separated by actual maturity, not by wishful symmetry in the UI.
