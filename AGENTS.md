### General Rules

- This rule applies to **ALL identifiers** we create, without exception, in the appropriate language (shell/haskell/etc)
- Use the appropriate casing convention for each language (camelCase for JS/TS and Haskell term-level bindings, snake_case for Python/Rust, PascalCase for types/classes/modules where applicable) please apply also to all languages we have not covered including shell scripts, env variables, and configuration file identifiers we create for example.
- Global constants use `SCREAMING_SNAKE_CASE` with `_CHIRHO` suffix where the language syntax supports it; if the language does not permit uppercase term bindings (for example standard Haskell values), use the closest idiomatic compilable form while still suffixing with `Chirho`
- File and directory names follow language conventions (kebab-case for JS/TS paths, snake_case for Python/Rust)
- API and HTML routes use kebab-case with `-chirho` suffix regardless of language

### Current Pipeline State (as of 2026-03-13)

The compiler has a working 10-phase pipeline wired end-to-end in `rhasky-driver-chirho`, capable of parsing Haskell source, checking pattern exhaustiveness, and evaluating via the STG machine:

1. **Lex** — `rhasky-syntax-chirho` tokenizer
2. **Layout** — `rhasky-syntax-chirho` layout rule insertion (braces/semicolons)
3. **CST Parse** — `rhasky-parser-chirho` concrete syntax tree (green tree)
4. **AST Lower** — `rhasky-ast-chirho` abstract syntax tree from CST
5. **Name Resolve** — `rhasky-naming-chirho` scope resolution with multi-module import support; `ModuleIfaceChirho` represents compiled module public APIs (exported values/types/constructors/methods); import resolution handles unqualified, qualified, aliased, hiding, and explicit import list specs; `NameEnvChirho` supports qualified name lookup (`Module.name` style); local definitions shadow imports
6. **Kind Infer** — `rhasky-typing-chirho::kind_chirho` kind inference with unification for higher-kinded types; `KindChirho` (Star, Arrow, Var, Constraint); `KindEnvChirho` with builtins; infers kinds for data/newtype/class/type-alias declarations; validates type application kind consistency; defaults unconstrained kind variables to `*`; wired into driver between name resolution and type inference
7. **Type Infer** — `rhasky-typing-chirho` Hindley-Milner Algorithm W with unification, type schemes, let-generalization; typeclass infrastructure fully integrated (PredChirho, QualTyChirho, ClassEnvChirho with instance resolution, context reduction, deferred predicate collection, predicate partitioning at generalization, constrained polymorphic type schemes)
7. **Exhaustiveness Check** — `rhasky-typing-chirho::exhaust_chirho` pattern match exhaustiveness and redundancy checking; builds TypeConEnvChirho (type→constructors mapping with built-in Bool/Maybe/Either/Ordering/List); checks case expressions and multi-equation function bindings for missing constructors (E0400) and unreachable patterns (W0401); handles wildcards, variables, as-patterns, literals, and nested sugar; wired into driver between type inference and desugaring
8. **Desugar → Dict Pass → Core → Simplify → Backends** — `rhasky-core-chirho` System FC-style Core IR with AST-to-Core desugaring (scope-tracked variable binding via DesugarOutputChirho, built-in operator recognition for PrimOp emission, two-pass pre-binding for let/where with recursive let detection via free-variable analysis, all 12 PatChirho variants handled including bang/lazy patterns), dictionary-passing transform (dict_chirho.rs: dictionary layouts, method selectors, dictionary lambda wrapping for constrained bindings), Core-to-Core simplifier (beta reduction, dead code elimination, case-of-known-literal, constant folding for PrimOp on literal args); `PrimOpChirho` variant in `CoreExprChirho` maps built-in operators (+, -, *, div, mod, ==, /=, <, <=, >, >=, negate) to `#`-suffixed primop names and compiles to native instructions in both backends (LLVM: add/sub/mul/sdiv/srem/icmp; WASM: i64.add/sub/mul/div_s/rem_s/eq/ne/lt_s/le_s/gt_s/ge_s)
9. **STG Evaluation** — `rhasky-driver-chirho::stg_lower_chirho` Core→STG lowering (code table generation, closure allocation, constructor tag mapping, argument register binding, PrimOp lowering to `CodeChirho::PrimChirho`); `rhasky-runtime-chirho::eval_chirho` STG machine execution (Enter/Apply/Return loop, thunk evaluation with blackholing, function application with PAP support, case dispatch, primitive operations with lazy thunk forcing via `PrimOpChirho` stack frames, step limits); accessible via `eval_source_chirho` convenience function
10. **Garbage Collection** — `rhasky-runtime-chirho::gc_chirho` mark-sweep GC for the STG heap; `GcConfigChirho` (configurable alloc threshold + min heap size); `GcStateChirho` tracks mark bits, allocation counter, cycle counter, and free list; `collect_chirho` performs BFS marking from roots then sweep with tombstone replacement; root extraction from stack frames and argument registers; integrated into `MachineChirho` evaluator — GC triggers automatically after allocation threshold is reached
11. **FFI** — `rhasky-runtime-chirho::ffi_chirho` foreign function interface; `FfiTypeChirho` (Int, Double, Char, String, Ptr, Void, Bool, StablePtr, FunPtr); `FfiValueChirho` with bidirectional marshalling to/from `ValueChirho`; `FfiCallConvChirho` (CCall, StdCall, CApi, Prim, JavaScript); `FfiSafetyChirho` (Safe, Unsafe, Interruptible); `ForeignTableChirho` registry with callback-based dispatch; built-in foreign functions (putChar#, putStr#, exitWith#, sin#, cos#, sqrt#); AST `ForeignDeclChirho` extended with `ForeignDirectionChirho` (Import/Export) and `safety_chirho` field
