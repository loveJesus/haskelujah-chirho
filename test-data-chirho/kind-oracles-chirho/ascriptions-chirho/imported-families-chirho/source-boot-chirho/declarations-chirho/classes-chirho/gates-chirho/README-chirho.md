# Boot-class checkpoint gates Chirho

`final-chirho.json` records the pre-annotation-repair freeze. The later
`after-annotations-chirho.json` records the actual checkpoint command lines,
output, exits and source hashes. Its completion flag is set only after every command finishes and the
HEAD, tracked diff, changed/new source path set and file hashes remain stable.
The deleted validity root is recorded separately from its replacement modules.

Test commands have no ignored-test selector or name filter. Clippy exit zero is
not warning-free status; count and inspect its recorded warning messages.
Cargo builds use three jobs; the full driver suite uses twelve test threads
on the eighteen-logical-CPU host. This is concurrency, not test exclusion.

`classes-after-chirho.jsonl`, `injectivity-after-chirho.jsonl` and
`syntax-after-chirho.jsonl` replay78/10/12 independent reference observations
against the post-repair CLI. The first two agree completely; syntax keeps S5/S9
as explicit disagreements. Seven default-annotation controls agree separately
under `../default-annotations-chirho/`, while its six scope follow-ups agree
only2/6 and remain open. A completed process or a green gate does not upgrade
those reference disagreements to implemented features.
