# Qualified builtin alias agreement Chirho

This directory generates and holds the evidence for one table (row 608):
`crates/haskelujah-typing-chirho/src/infer_chirho/builtins_chirho/qualified_alias_agreement_chirho.rs`.

## What the table decides

Driver Phase 3.9 types a qualified import's `Q.x` from the `Module.x` key when one exists. Without
a key, a qualified import of a builtin module got the accept-anything placeholder `forall a. a`, so
`print (L.reverse xs)` defaulted Show to Int and failed natively.

Now a qualified import of builtin module M that exposes `x` with no `M.x` key takes the bare
builtin scheme of `x` exactly when `(M, x)` is in the table. Everything else keeps the placeholder.
An entry means that GHC 9.14.1 types `M.x` as the bare scheme of `x`, under the contract below.
No build or gate runs GHC; the table is regenerated by hand.

## Regenerate

From the repository root, with GHC 9.14.1 on the path:

```
python3 -I test-data-chirho/qualified-alias-agreement-chirho/generate_chirho.py
```

It takes about four minutes, most of it the ghci session. It runs these steps:

1. **List the exports.** The ignored Rust test `dump_qualified_alias_queries_chirho` lists every
   builtin export with no `module.name` key, by canonical name. That covers the values, plus the
   constructors and class methods of exported types.
2. **Ask GHC.** One ghci session imports every listed module that these packages expose, all
   qualified, and asks `:type` for each export: array, base, bytestring, containers, deepseq,
   directory, filepath, mtl, process, stm, text, time and transformers.
3. **Write the outputs.** The ignored Rust test `write_qualified_alias_table_chirho` normalizes
   both sides and writes the table, `counts-chirho.txt` and `disagreements-chirho.tsv`.

Intermediate files live in a temporary directory and are not inputs to anything. The run is
deterministic: regenerating on two bases gave byte-identical outputs.

## The normalization contract

One Rust function, `normalized_type_chirho` in
`crates/haskelujah-driver-chirho/tests/typing_integration_chirho/qualified_alias_agreement_chirho.rs`,
applies to GHC's `:type` text and to the printed bare scheme alike:

1. Tokenize, and strip module qualifiers from names and operators.
2. Drop a leading `forall vs.`.
3. Expand `String` and `FilePath` to `[Char]`, and no other synonym. `Rational` stays as written,
   so a pair that would need it disagrees.
4. Split at the first top-level `=>`, and split a parenthesized context at its top-level commas.
5. Drop a `HasCallStack` constraint.
6. Rename type variables `v0`, `v1`, ... in order of first appearance, in the body and then in the
   context.
7. Sort the constraints, and print `(C1, C2) => body`, or the body alone, with single spaces.

- Container modules have no entries. That falls out of the data rather than a list: Data.Map,
  Data.Set, Data.IntMap, Data.Sequence, Data.Text, Data.ByteString and Data.List.NonEmpty.
- The disagreements are named residuals, each for a row of its own:
  - GHC's Foldable-generic functions against list-only bare schemes;
  - Data.Maybe's over-general bare schemes;
  - a String-only `intercalate`;
  - missing constraints on `forever`, `mapM` and `sequence`.

## Checks that guard the table

All of these run in normal gates, in the same test file:

- `the_contract_normalizes_both_sides_alike_chirho`: the contract on spellings that must meet,
  and on spellings that must stay apart.
- `the_table_is_sorted_and_unique_chirho`: sorted bytewise by (module, name), with no duplicates.
- `every_entry_is_an_unkeyed_builtin_export_that_still_agrees_chirho`: each entry is a builtin
  export with no module key, and today's bare scheme still prints to the recorded GHC type. An
  edit to a bare scheme fails here until the table is regenerated.
- `phase_3_9_reads_the_table_and_nothing_else_chirho`: over every unkeyed builtin export, the
  decision gives the bare scheme exactly for the table's entries.
